# 渝安青澜工程路线图

## 里程碑

- M0 工程基础：项目可构建、设计系统、导航与演示数据骨架。
- M1 核心界面：首页、安葬双轨、追忆私密域、树洞双池、个人中心。
- M2 体验完善：适老、伦理与隐私、测试、演示脚本和 APK。

## Issue 1 初始化 Android Compose 工程

目标：创建可在现有 Windows 环境稳定构建和运行的 Android 工程。

实现建议：使用 Kotlin、Compose、Material 3、Gradle Kotlin DSL；单 `app` 模块；配置 Compile/Target SDK 36、Min SDK 26；加入 Gradle Wrapper、基础主题、测试依赖和 `local.properties.example`。

验收标准：`gradlew.bat assembleDebug` 与单元测试通过；可安装到 `emulator-5560`；仓库不提交本机 SDK 路径和构建产物。

依赖：无。里程碑：M0。标签：foundation、android、priority-high。

## Issue 2 建立设计系统并接入视觉素材

目标：形成统一的自然、温暖、克制的 Compose 组件基础。

实现建议：定义多主题色板、排版、间距、8dp 以内圆角、按钮、分段切换、列表、时间轴和状态组件；接入启动页、树葬、花葬、草坪葬和宠物纪念素材；为图片补充无障碍描述。

验收标准：提供组件预览页；三种葬式主题可切换；普通与适老字号下无截断、重叠；素材来源与用途在清单中可追溯。

依赖：Issue 1。里程碑：M0。标签：design-system、assets、ui。

## Issue 3 实现 5-Tab 应用外壳与本地演示数据层

目标：让 22 个页面拥有稳定导航、统一状态和可重置的演示数据。

实现建议：单 Activity、Navigation Compose、顶层 Scaffold；每个 Tab 保留回退栈；以本地 JSON 和假仓库提供固定延迟、加载、成功与空状态；人宠模型和数据集合强类型隔离。

验收标准：5 个 Tab 可切换且回退行为正确；22 个页面均有可达路由；人宠切换不串数据；可从设置一键恢复初始演示状态。

依赖：Issue 1。里程碑：M0。标签：navigation、demo-data、architecture、priority-high。

## Issue 4 实现启动页与首页总览

目标：完成品牌开场、首页人宠入口、智能匹配和政策补贴演示。

实现建议：启动页使用无文字背景素材叠加 Compose 品牌文字；首页包含 Banner、追忆入口、人/宠分段切换、快捷功能与资讯；智能匹配用本地规则生成推荐；政策页使用区县筛选、FAQ 和演示预审。

验收标准：页面 00-03 完整可用；从启动页进入首页；人宠入口状态清晰；政策和价格均带演示标识；无真实个人信息提交。

依赖：Issue 2、Issue 3。里程碑：M1。标签：feature-home、ui、priority-high。

## Issue 5 实现人类生态安葬演示流程

目标：展示树葬、花葬、草坪葬的选择、详情、价格、订单和点位导航。

实现建议：用共享详情模板承载不同主题和数据；套餐突出 2000 元以内基础款与 2000-5000 元升级款；订单采用纵向时间轴；导航使用固定园区图和预置点位，不申请真实定位权限。

验收标准：页面 04、07-10 可连贯演示；费用包含与不包含项清楚；点位高亮、路线和祭扫须知可查看；无重庆内河江葬入口。

依赖：Issue 2、Issue 3。里程碑：M1。标签：feature-burial、human-track、priority-high。

## Issue 6 实现宠物安葬独立流程

目标：在一致的产品语言下展示宠物告别服务，同时明确其与人类服务的差异和隔离。

实现建议：顶部双轨切换进入独立宠物数据源；宠物页强调无害化处理前置、无民政补贴、独立场地和宠物纪念树；复用组件但不复用人类业务文案与订单对象。

验收标准：页面 05-06 可用；切换前后无数据串联；关键差异在首屏可见；返回人类轨道时恢复原浏览位置。

依赖：Issue 5。里程碑：M1。标签：feature-burial、pet-track、privacy。

## Issue 7 实现人宠私密追忆空间

目标：完成纪念馆、生命故事、思念日记、AI 伦理前置与异地代祭演示。

实现建议：追忆首页提供人/宠分段切换；纪念馆和故事使用本地虚构人物或宠物资料；日记默认仅本人可见；AI 页面强制先阅读授权、用途、访问与销毁规则，再进入素材选择和预置生成结果；代祭完成影像归档到纪念馆。

验收标准：页面 11-17 可连贯演示；人宠纪念数据严格隔离；AI 伦理页不可跳过；无实时逝者对话；所有上传与销毁均为本地演示。

依赖：Issue 2、Issue 3。里程碑：M1。标签：feature-memorial、ai-ethics、privacy、priority-high。

## Issue 8 实现人间与生灵树洞双池

目标：提供匿名弱连接情绪陪伴，并从交互上证明两个内容池相互隔离。

实现建议：入口页先选人间或生灵；各池均支持寄信、随机拾信、换一封、收藏、举报和轻回应；仅用点灯、叶片或花朵表达关怀，不显示计数；提供本地敏感内容拦截和演示举报反馈。

验收标准：页面 18-20 可用；跨池搜索或切换不会出现另一池内容；无点赞、粉丝、私信、楼中楼或热度排名；举报入口易发现。

依赖：Issue 2、Issue 3。里程碑：M1。标签：feature-treehole、safety、privacy、priority-high。

## Issue 9 实现个人中心与设置

目标：统一呈现业务档案、纪念资源、素材销毁、适老与树洞设置。

实现建议：按业务、追忆、隐私和系统设置分组；提供树洞总开关、内容权限、举报记录、AI 素材一键销毁、适老模式和演示数据重置；危险操作使用确认对话框并反馈结果。

验收标准：页面 21 可用；设置经 DataStore 持久化；树洞关闭后入口状态同步；销毁操作不会影响另一轨道数据；可一键重置演示。

依赖：Issue 3、Issue 7、Issue 8。里程碑：M1。标签：feature-profile、settings、accessibility。

## Issue 10 完成适老化、隐私与伦理验收

目标：把适老和伦理边界落实到全部页面，而不是停留在说明文字。

实现建议：检查动态字体、对比度、48dp 点击热区、读屏描述、减少动态效果；统一演示数据标识、隐私权限、删除确认和免责声明；建立人宠隔离自动测试与内容安全检查表。

验收标准：普通与适老模式下关键链路无截断或遮挡；TalkBack 可理解主要操作；伦理底线逐项有界面证据和测试；不出现真实个人敏感数据。

依赖：Issue 4-9。里程碑：M2。标签：accessibility、privacy、qa、priority-high。

## Issue 11 完成自动化测试与模拟器回归

目标：保证评审现场可以稳定重复演示。

实现建议：为假仓库、匹配规则、双轨隔离和设置编写单元测试；为 5-Tab、关键链路、返回键和适老模式编写 Compose UI 测试；在 `Pixel_7_API_36` 的 `emulator-5560` 上执行安装和回归。

验收标准：测试命令通过；冷启动、旋转、后台恢复和连续演示无崩溃；记录已知限制与回归结果；关键页面截图经过桌面与模拟器视觉检查。

依赖：Issue 4-10。里程碑：M2。标签：testing、qa、android。

## Issue 12 交付演示 APK 与讲解脚本

目标：形成可直接展示和交接的项目成果。

实现建议：生成 Debug APK；编写 5-8 分钟演示脚本，覆盖首页双轨、安葬差异、私密追忆、树洞双池和设置；补充构建、安装、重置与故障排查说明；整理最终截图。

验收标准：新环境可按 README 构建并安装；APK 在 API 36 模拟器运行；演示脚本与产品基线一致；仓库无密钥、真实个人信息和构建产物。

依赖：Issue 11。里程碑：M2。标签：release、documentation、demo。
